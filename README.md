# 🔧 Мастерская v2

Локальная CRM для мастера по ремонту телефонов: **приём заказа → ремонт → акт →
выдача**, с базой клиентов, учётом доходов и расходов и сводкой по прибыли.

Всё работает на вашем компьютере: данные лежат в локальной базе SQLite, интернет
не нужен.

## Что умеет

- **Заказы** — приём, статусы, сроки, карточка с журналом действий.
  Статусы: Новый → Диагностика → В работе → Ждёт запчасть → Готов → Выдан
  (+ Отказ клиента, Гарантийный).
- **Акты** — приёмный акт и акт выполненных работ с реквизитами мастерской,
  подписями и суммой прописью. Печать в PDF прямо из браузера.
  Приёмный акт печатается **в двух экземплярах на одном листе A4** — лист
  разрезается по пунктирной линии: верхняя половина отдаётся заказчику,
  нижняя остаётся в мастерской.
- **Клиенты** — база с историей ремонтов, выручкой, средним чеком и прибылью.
- **Финансы** — доходы и расходы, сводка за период (выручка, себестоимость,
  прибыль, маржа), экспорт в Excel.
- **Задачи по заказу** — «позвонить клиенту», «заказать деталь», «напомнить»
  с выбором срока. Виджет **«Что сделать сегодня»** на дашборде (просроченные,
  на сегодня, позже), счётчик в меню и кнопка «📞 Позвонить» прямо из задачи.
  Любую задачу можно **изменить** — кнопкой «✎» или кликом по тексту.
- **Напоминание клиенту** — ссылки для SMS, Telegram и Viber с готовым текстом
  о готовности заказа.
- **Дашборд** — блок «Сегодня» (выручка, прибыль и список выданных за день
  заказов, обновляется раз в минуту), показатели за период, новые заказы,
  готовые к выдаче, заказы по всем этапам с быстрым переводом статуса.
- **Резервные копии** — автоматически, по расписанию, плюс выгрузка всех
  данных в JSON для переноса на другой компьютер.
- **Обновление из GitHub** — кнопка в настройках: проверка и установка новой
  версии с перезапуском сервера.
- **Диагностика** — отчёт о системе, базе и журнале одной кнопкой, если что-то
  пошло не так.

## Чего больше нет (по сравнению с первой версией)

- **Парсинга цен** с `shop.topset.by` — больше не нужен.
- **Вкладки «Заказ запчастей»** (заказы поставщику) — больше не нужна.
- **Списка деталей в заказе** — вместо него одна сумма себестоимости,
  которую вы вводите сами. Так проще и не нужно вести склад.

## Требования

- Windows 10/11, macOS или Linux
- **Node.js 22 или новее** — ставить его вручную не нужно: установщик
  возьмёт его сам, если не найдёт или если версия не подходит (см. ниже)

> Почему 22, а не «любая»: модуль SQLite (`better-sqlite3`) — нативный, и для
> него существуют готовые бинарники под Node 22, 24, 25 и 26. Под Node 20 их
> нет, поэтому установка попыталась бы собрать модуль из исходников — на
> Windows это требует Visual Studio и часто заканчивается ошибкой. Установщик
> сам ставит Node 22 в папку `.node`, если системная версия не подходит.

## Установка

### Windows — пошагово

1. Установите **Git для Windows** (нужен для скачивания приложения):
   [git-scm.com/download/win](https://git-scm.com/download/win) → «Next» до конца.
   Включите галочку **«Git from the command line and also from 3rd-party software»**.

2. Откройте **командную строку** (клавиши `Win` → напечатать `cmd` → Enter)
   и выполните две команды:

   ```bat
   git clone https://github.com/mm2231/masterskaya
   cd masterskaya && install.cmd
   ```

3. Установщик сам:
   - проверит версию Node.js — если Node не установлен или версия не подходит,
     поставит подходящую (Node 22) в папку `.node` внутри проекта, без прав
     администратора;
   - установит зависимости по `package-lock.json`;
   - создаст `.env` со случайным ключом сессии;
   - применит миграции и заполнит справочники;
   - соберёт интерфейс.

4. После установки двойным щелчком запускайте **«Запустить мастерскую.bat»** —
   сервер поднимется, а страница откроется в браузере сама.

> **Node.js ставить отдельно не нужно.** Если он уже установлен и версия 22, 24,
> 25 или 26 — установщик использует системный. Версии 20 и старше не подходят:
> для них у модуля SQLite нет готовых бинарников, и установка попыталась бы
> собрать его из исходников (на Windows это почти всегда заканчивается ошибкой).

### macOS / Linux — две команды

```bash
git clone https://github.com/mm2231/masterskaya
cd masterskaya && ./install.sh
```

Дальше — двойной щелчок по `Запустить мастерскую.command`.

### Если установка не удалась

**Ошибка `EPERM` / `operation not permitted`** — антивирус или «Защита Windows»
держит файлы в папке `node_modules`. Закройте антивирус, удалите папку и
запустите установку заново:

```bat
cd C:\Users\ИМЯ\masterskaya
rmdir /s /q node_modules
install.cmd
```

**Ошибка `No prebuilt binaries found` или ошибка сборки `node-gyp`** — старая
версия приложения или Node.js 20. Обновитесь и поставьте Node 22+:

```bat
cd C:\Users\ИМЯ\masterskaya
git pull
install.cmd
```

**«Node.js слишком старый»** — запустите `install.cmd`, он поставит нужную
версию сам.

**Всё равно не работает** — запустите приложение и откройте
**«Настройки» → «Диагностика» → «Скопировать отчёт»**, пришлите отчёт.
В нём: система, версия Node, порт, путь к базе и последние строки журнала.

### Реквизиты мастерской

Заполните их в разделе **«Настройки»** в самом приложении — они
подставляются в приёмный акт и акт выполненных работ. Либо сразу в файле

```

WORKSHOP_OWNER=Иван Иванов
WORKSHOP_UNP=УНП
WORKSHOP_ADDRESS=адрес

```

### Запуск

Двойным щелчком:

- **macOS** — `Запустить мастерскую.command`
- **Windows** — `Запустить мастерскую.bat`

Скрипт поднимает сервер в фоне, **дожидается его готовности** и только потом
открывает браузер. Если сервер не поднялся — в окне будет причина и последние
строки журнала. Если желаемый порт занят, приложение возьмёт следующий свободный
и напишет, какой.

Остановить:

- **macOS** — `Остановить мастерскую.command`
- **Windows** — `Остановить мастерскую.bat`

Из командной строки:

```bash
npm start
```

Откройте <http://127.0.0.1:8080/>. В консоли появятся адреса: на этом
компьютере и в локальной сети (чтобы открыть с телефона).

Журнал сервера пишется в `data/app.log`.

Для разработки (с горячей перезагрузкой):

```bash
npm run dev        # API с горячей перезагрузкой
npm run dev:web    # фронт на :5173 с прокси на API
```

## Задачи

Задача привязана к заказу: «Позвонить клиенту», «Заказать деталь», «Напомнить
о готовности». Срок — дата и необязательное время.

- Создаются из карточки заказа (вкладка «Задачи») или с дашборда («＋ Задача»).
- На дашборде виджет «Что сделать сегодня»: просроченные (красным), на сегодня и
  позже (сворачивается).
- В меню — счётчик открытых задач; красным, если есть просроченные.
- Чекбокс отмечает задачу выполненной, кнопка «📞» звонит клиенту.
- **Изменение задачи** — кнопка «✎» у задачи (на всех страницах, где есть
  список) или клик по самому тексту. Меняются формулировка и срок; срок можно
  убрать ссылкой «убрать» рядом с полем.
- Удаление заказа удаляет его задачи (каскад).

Тексты-шаблоны и правила сроков — в `packages/shared/src/tasks.ts`.

## Условия выполнения работ

В приёмный акт и в акт выполненных работ печатается один и тот же блок
условий (6 пунктов): порядок определения стоимости, ответственность за
данные и SIM-карты, скрытые дефекты, исключения из гарантии, аналоговые
запчасти, срок хранения устройства.

Текст задан в одном месте — `packages/shared/src/terms.ts`, — поэтому бланки
не могут разойтись. Чтобы изменить формулировки, правьте этот файл.

В приёмном акте сумма не печатается: по условиям стоимость определяется
после диагностики и согласуется с заказчиком. В акте выполненных работ
итоговая сумма указывается.

## Как считаются деньги
Единая формула, чтобы не запутаться:

```
Выручка      = сумма клиенту по заказам, ВЫДАННЫМ в периоде
             + прочие доходы (мелкие работы без заказа)
Себестоимость = сумма себестоимости по выданным заказам
Прибыль       = Выручка − Себестоимость − расходы
Маржа         = Прибыль / Выручка × 100
```

- Дата выдачи ставится автоматически при переводе заказа в статус «Выдан».
  Если заказ вернули из «Выдан», дата сбрасывается — деньги ещё не получены.
- Себестоимость — одна сумма на заказ, вводится вручную.
- Расходы (аренда, инструмент, реклама) записываются отдельно на странице
  «Финансы» и попадают в прибыль периода.

### Как не потерять, куда ушли деньги

В каждой записи о движении денег есть **категория** и **комментарий**:

- **Категория** — поле с подсказками: выберите из списка (Аренда, Налоги,
  Запчасти, Закупка техники…) или впишите свою. Новая категория заводится
  автоматически и в следующий раз будет в подсказках.
- **Комментарий** — свободный текст: «закупка 5 телефонов на запчасти»,
  «налоги за 3 месяц». Виден в таблице «Движение денег» и в выгрузке в Excel.

Запись можно **изменить** в любой момент — кнопка «Изменить» в строке
(сумма, категория, дата, комментарий). Это спасает, когда про комментарий
забыли при вводе: дописать его можно позже, а не искать в бумажках.

Фильтры «Все / Расходы / Доходы» над таблицей помогают разобрать, куда
уходили деньги за период.

## Перенос данных из первой версии

Если у вас осталась старая база `topset.db`:

```bash
npm run import:legacy -- /путь/к/topset.db
```

Что переносится: клиенты, заказы (номер акта → номер заказа, статусы по
маппингу), сумма закупки по позициям → себестоимость, мелкие доходы → доходы.
Что не переносится: кэш цен парсера и заказы поставщику — этот функционал снят.

Импорт можно запускать повторно: дубликаты не создаются.

## Выгрузка и перенос данных

В разделе «Настройки» есть кнопка «Скачать все данные (JSON)» и загрузка
файла назад. Файл содержит клиентов, заказы, события, акты, платежи и расходы —
его можно сохранить на флешку или перенести на другой компьютер. Импорт
идемпотентный: клиенты сверяются по телефону, заказы — по номеру, платежи — по
дате и сумме, поэтому повторная загрузка ничего не дублирует.

## Если что-то не работает

### Приложение не запускается

Двойной щелчок по «Запустить мастерскую» показывает **причину**: последние
строки журнала и подсказку. Типичные сообщения:

| Что написано | Что значит | Что делать |
|---|---|---|
| «Порт 8080 занят — использую свободный 8081» | Порт занят другой программой | Ничего: приложение уже поднялось на другом порте |
| «модуль SQLite не подходит к этой версии Node» | Устаревший Node.js | Запустите `install.cmd` — он поставит подходящую версию |
| «Cannot find module .../dist/server.js» | Приложение не собрано | Запустите `install.cmd` |
| «EPERM: operation not permitted» | Антивирус держит файлы | Закройте антивирус, удалите `node_modules`, запустите `install.cmd` |

Порт из `.env` (`PORT=8080`) можно поменять на любой свободный вручную.

### Собрать отчёт о состоянии

В разделе **«Настройки» → «Диагностика»** есть кнопка «Скопировать отчёт».
В отчёте: система и версия Node, порт, путь к папке и базе, количество
записей и хвост журнала. Скопируйте и пришлите — по нему видно причину
без копания в файлах.

### Журнал

`data/app.log` — последние события сервера. Открыть можно обычным блокнотом.

### Страница открывается, но «не работает»

Если в адресной строке `http://127.0.0.1:8080/` и страница пустая — сервер
не поднялся. Посмотрите журнал `data/app.log` или запустите
«Запустить мастерскую» ещё раз: скрипт покажет причину.

Если открылась старая версия страницы — нажмите `Ctrl+F5` (принудительное
обновление): браузер кэширует файлы интерфейса.

## Обновление приложения

В разделе **«Настройки» → «Обновление приложения»**:

- **«Проверить обновления»** — показывает установленную версию (коммит и
  дата) и есть ли новая на GitHub;
- **«Установить и перезапустить»** — забирает изменения, ставит зависимости,
  собирает приложение и перезапускает сервер. Страница откроется заново.

База данных при обновлении не затрагивается — меняется только код.
Журнал операции пишется в `data/update.log`.

Из командной строки то же самое:

```bash
npm run update:check     # проверить
npm run update:install   # установить
```

Обновление выполняется только в режиме fast-forward (`git pull --ff-only`) —
история коммитов не переписывается, ваши локальные изменения не теряются.
Команды git вызываются с фиксированными аргументами.

### Обновление вручную (Windows)

Если кнопка обновления не работает или после обновления что-то сломалось:

```bat
cd C:\Users\ИМЯ\masterskaya
git pull
install.cmd
```

`install.cmd` применит новые миграции и пересоберёт приложение. База данных
не затрагивается — обновляется только код.

Если `git pull` ругается на локальные изменения (у вас правили файлы вручную):

```bat
git stash
git pull
```

Файлы, которые вы правили, лежат в `git stash` — их можно вернуть командой
`git stash pop`.

Требуется установленный `git` — он и так нужен для клонирования.

## Перенос на другой компьютер

Нужно перенести **только базу данных**. Код ставится заново из GitHub.

### 1. На этом компьютере — снять копию базы

```bash
npm run data:backup
```

Копия делается через SQLite backup API — приложение можно не останавливать.
Файл появится в `data/exports/`. Скопируйте его на флешку (или передайте
любым способом).

### 2. На новом компьютере — установить из GitHub

```bash
git clone https://github.com/mm2231/masterskaya
cd masterskaya && ./install.sh
```

Windows: `install.cmd` вместо `./install.sh`.

### 3. Загрузить базу

В разделе **«Настройки» → «Резервная копия данных»** нажмите
«⬇ Скачать все данные (JSON)» — получите файл для переноса. На новом
компьютере загрузите его обратно через «Загрузить файл с данными».

Или в командной строке:

```bash
npm run data:import -- путь/к/файлу.json
```

Импорт идемпотентный: клиенты сверяются по телефону, заказы — по номеру,
платежи — по дате и сумме. Повторная загрузка ничего не дублирует.

**Альтернатива:** скопировать папку `data` целиком — это весь ваш архив
(база, бэкапы, журналы).

### Проверка, что копия цела

```bash
npm run backup:check
```

Скрипт развернёт последнюю копию во временную папку, проверит целостность
и сверит количество заказов и клиентов с рабочей базой.

### Если нужен вариант «вообще без Node.js»

Приложение можно упаковать в переносимый вид — папку, которая запускается
двойным щелчком:

```bash
npm run build:portable -- --platform=win32-x64    # для Windows
npm run build:portable -- --platform=darwin-x64   # для macOS
npm run build:portable                           # для текущей ОС
```

В корне проекта появится папка `portable/<платформа>` и архив `.zip`:

```
portable/windows-x64/
├── Запустить мастерскую.bat     ← двойной клик: сервер + браузер
├── Остановить мастерскую.bat    ← закрывает приложение
├── Импортировать данные.bat    ← загрузка базы с другого компьютера
├── ИНСТРУКЦИЯ.txt
├── app/                         ← программа (обновляется целиком)
└── data/                        ← база, бэкапы, журнал (не трогаем при обновлении)
```

Пакет содержит готовый модуль SQLite под Windows/macOS для **Node 22, 24, 25
и 26** — при запуске скрипт сам подставляет подходящий по версии Node.

## Ограничения

- Приложение рассчитано на одного мастера: нет ролей и филиалов.
- PDF формируется браузером (диалог «Сохранить как PDF») — отдельные
  библиотеки не нужны.
- Уведомления клиенту по SMS/Telegram пока не подключены — есть только
  ссылки на мессенджеры.
